# Handoff 2026-10-06: US Senior Care Facility Finder

## What happened
- 26,658 care-facility rows moved out of the US Portal Atlas (12 sources, `site.json` sources) into this portal at
  https://senior-care.navi-index.com/ (Cloudflare Workers Static Assets, Worker `portal-us-senior-care`, not Contabo).
- One portal with a type facet, not two: every demand is "<type> near me" (DataForSEO US 2026-10-06: nursing homes near me
  201,000, assisted living near me 165,000, in home care near me 49,500, home health care near me 33,100, hospice near me
  33,100, community health center near me 14,800), so state/city pages that mix types serve the same searcher.
- Atlas 301s: block `senior-care` in Atlas `data/facility-moves.json` (prefixes + 463 explicit slugs + /nursing-homes paths).

## Where it goes wrong
- `deploy-cf.py` must be run from a fresh copy of the main file. If you run the checkout's own file, it fetches main into
  the same path and does NOT re-exec, so the old code runs (2026-10-06: child sitemaps were missing for that reason).
- Every deploy re-uploads all ~37k assets (~1 hour on the ops machine, load average was ~5,000 that day).
- Assets ignore the query string: pagination is `/page/N/`. `/?page=2` returns page 1 (canonical is `/`), harmless.
- `/api/items` is served from row shards, not one `__rows.json` (that would be ~25 MB, at the per-asset limit).
- 103 rows have no city/state (Pacific islands HRSA grantees, Canadian franchisees in the home-care directory). They are
  kept with type only.
- Loops (PO / product / SEO) are not created yet: `new-loop.py` says registration in agent-loops.json starts on the owner's
  instruction (docs/loop-design.md §4).
